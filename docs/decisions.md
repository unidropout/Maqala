## 001. API внутри Next.js

**Дата:** 2026-10-31
**Статус:** принято

**Решение:** API (ТЗ §8) делается на Next.js route handlers в том же проекте, что и сайт.

**Почему:** один проект, один деплой и один язык (TypeScript) для сайта и API. На объёмах MVP отдельный сервис не нужен.

**Последствия:** код доступа к базе держим в отдельном модуле, чтобы при росте нагрузки API можно было вынести в отдельный сервис без переписывания страниц.

## 002. MVP без бюджета

**Дата:** 2026-10-31
**Статус:** принято

**Решение:** MVP запускается только на бесплатных тарифах: сайт на Vercel по адресу `maqala.vercel.app`, база на Supabase (до 500 МБ), код и CI на GitHub. Домен maqala.kz покупается после MVP.

**Почему:** бюджета на домен и хостинг нет. Бесплатно зарегистрировать домен .kz нельзя, а по правилам зоны .kz сайт должен размещаться на серверах в Казахстане.

**Последствия:**
- в продакшен-базе сначала только статьи Казахстана, чтобы уложиться в 500 МБ;
- проверка скорости поиска на 1 млн записей делается локально;
- при покупке домена .kz отдельно решается, где размещать сайт.

## 003. Единственный источник в MVP: OpenAlex

**Дата:** 2026-10-31
**Статус:** принято

**Решение:** в MVP данные берутся только из OpenAlex. CORE, Crossref и казахстанские репозитории подключаются после MVP.

**Почему:** OpenAlex закрывает основную массу метаданных, страны авторов и темы, у него открытый API. Один источник позволяет быстрее дойти до работающего продукта.

**Последствия:** коннектор изолирован, чтобы следующие источники добавлялись рядом без изменения сайта.

## 004. Храним только метаданные

**Дата:** 2026-10-31
**Статус:** принято

**Решение:** храним только метаданные и ссылки на оригинал. Полные тексты и PDF не копируем.

**Почему:** юридические требования (ТЗ §10) и экономия места в бесплатной базе.

## 005. Авторы хранятся в jsonb внутри статьи

**Дата:** 2026-11-01
**Статус:** принято

**Решение:** авторы и их организации лежат в колонке `works.authors` (`jsonb`), отдельных таблиц авторов и организаций в MVP нет.

**Почему:** в MVP авторы нужны только для показа в карточке и на странице статьи (FR-4, FR-5). Поиска и страниц по авторам нет, а таблицы связей усложнили бы загрузку.

**Последствия:** если понадобятся страницы авторов или организаций, их вынесут в отдельные таблицы миграцией. Страны авторов уже вынесены в `works.countries` (массив с GIN-индексом) для фильтров.

## 006. Размер базы и бесплатный лимит Supabase

**Дата:** 2026-11-01
**Статус:** открыто, решить на этапе 5

**Факт:** 2000 статей занимают 29 МБ, из них 16 МБ — исходная запись `raw`. Все открытые статьи Казахстана (~109 тысяч) займут около 1,6 ГБ, а бесплатный Supabase даёт 500 МБ.

**Варианты:** не хранить `raw` в продакшене (оставить только локально), обрезать список авторов в `raw`, загружать в продакшен только часть статей (например, за последние годы).

**Последствия:** до этапа 5 храним всё; перед деплоем выбрать вариант и записать сюда.
