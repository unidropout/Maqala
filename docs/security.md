## Проверено и в порядке

- **Секреты.** `.env` в `.gitignore` и ни разу не попадал в историю git; паролей, токенов и личных почт в коде и истории нет; коммиты подписаны noreply-адресом GitHub. Репозиторий можно делать публичным.
- **SQL.** Все запросы параметризованы. В текст запроса подставляются только номера параметров, постоянные фрагменты и проверенное число страницы (`web/lib/works.ts`); коннектор пишет через `psycopg` с параметрами.
- **Входные данные API.** Год — только 4 цифры, страна — 2 буквы, страница — целое 1–500, запрос — до 200 символов, id — положительное целое; ошибки возвращаются как JSON без подробностей.
- **HTML.** Пользовательские данные выводятся только через React (экранирование). Единственный `dangerouslySetInnerHTML` — постоянный скрипт темы без внешних данных.
- **Авторизация, загрузка файлов, платежи** — в MVP их нет, атаковать нечего.
- **Ключ OpenAlex** передаётся в заголовке `Authorization`, а не в адресе, поэтому не попадает в логи и сообщения об ошибках.

## Зависимости

- `npm audit` после обновления: критических нет. Остались `postcss` 8.4.31 внутри Next.js (обрабатывает только наш CSS при сборке), `sharp` 0.34.5 (сжимает только наши картинки из `public/art`: загрузки нет, внешние адреса картинок не разрешены) и `minimatch` в ESLint (только разработка). Через сайт не эксплуатируются; уйдут с обновлением Next.js.
- `pip-audit`: зависимости коннектора чистые; уязвимости только в самом `pip` локального окружения.
