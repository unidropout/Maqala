# Техническое задание: Maqala

## 1. Общие сведения

**Название:** Maqala (казахское «мақала», «статья»).

**Домены:** основной **maqala.kz**, дополнительный **maqala.com** (редирект на основной, если свободен). Доступность доменов проверяется до покупки через регистратора.

**Цель:** веб-сайт, который собирает метаданные научных статей в открытом доступе из открытых источников, приводит их к единому формату и показывает в удобном, визуально выразительном интерфейсе с поиском и фильтрами. Отдельный акцент на научных работах Казахстана.

**Проблема:** открытые статьи разбросаны по множеству баз с неудобными интерфейсами, а казахстанская наука плохо видна и в международных каталогах, и в поиске.

**Ценность для пользователя:** найти бесплатную статью по теме и стране за несколько секунд и сразу перейти к оригиналу.

## 2. Целевая аудитория

- студенты и школьники, которым нужны бесплатные источники для работ;
- исследователи и преподаватели Казахстана и СНГ;
- журналисты и все, кому интересна открытая наука.

## 3. Границы проекта

**Входит в MVP:**
- сбор метаданных статей из OpenAlex;
- полнотекстовый поиск по названию и аннотации;
- фильтры: страна, год, область науки, язык, лицензия;
- карточка статьи со ссылкой на оригинал;
- страница страны (первой Казахстан) со статистикой;
- адаптивный интерфейс, светлая и тёмная темы.

**Не входит в MVP:**
- регистрация и личные кабинеты;
- монетизация и платные функции;
- хранение полных текстов и PDF на нашей стороне;
- рекомендации и ИИ-функции;
- загрузка статей пользователями;
- дополнительные источники кроме OpenAlex (подключаются после MVP).

## 4. Функциональные требования

**FR-1. Поиск.** Пользователь вводит запрос и получает релевантные статьи. Поиск идёт по названию и аннотации, заголовок весит больше. Поддерживаются русский, казахский и английский тексты.

**FR-2. Фильтры.** Сочетаются между собой:
- страна (по странам авторов, мультивыбор);
- год публикации (диапазон);
- область науки;
- язык статьи;
- тип лицензии.

Рядом с каждым значением фильтра показывается количество результатов.

**FR-3. Сортировка:** по релевантности, по дате, по числу цитирований.

**FR-4. Выдача.** Постраничная (или бесконечная прокрутка) с карточками: название, авторы, год, журнал, страны, значок лицензии, фрагмент аннотации.

**FR-5. Страница статьи.** Полные метаданные, аннотация, авторы с организациями, лицензия, кнопка «Читать оригинал» (прямая ссылка на источник), указание источника данных.

**FR-6. Страница страны.** Количество статей, распределение по годам и областям, список последних и самых цитируемых работ. Первая страна: Казахстан.

**FR-7. Главная страница.** Поисковая строка, подборка по странам (Казахстан выделен), несколько показательных статей, визуальные элементы в духе галерей уровня Awwwards.

**FR-8. Страница «О проекте».** Описание целей, список источников данных, контакт для запросов на удаление записи.

## 5. Нефункциональные требования

- **Производительность:** выдача поиска до 1 секунды при базе до 1 млн записей.
- **SEO:** каждая статья и страна имеют отдельный URL с серверным рендерингом, корректные meta-теги, `sitemap.xml`.
- **Адаптивность:** корректная работа от 360 px (телефон) до широких экранов.
- **Доступность:** контраст по WCAG AA, навигация с клавиатуры, alt-тексты.
- **Языки интерфейса:** в MVP один язык (русский), но архитектура сразу строится с поддержкой i18n для добавления казахского и английского.
- **Надёжность:** сбой одного источника данных не должен ломать сайт.
- **Безопасность:** секреты только в переменных окружения, параметризованные запросы к БД, ограничение частоты запросов к API.

## 6. Данные

### 6.1 Источники

| Источник | Назначение | Приоритет |
|---|---|---|
| OpenAlex | основная масса метаданных, страны, темы | MVP |
| CORE | открытые тексты, дополнительные записи | после MVP |
| Crossref | уточнение метаданных по DOI | после MVP |
| Репозитории вузов и журналы Казахстана | уникальный контент, «изюминка» | после MVP, по одному |

Перед подключением каждого источника изучаются и фиксируются в `docs/data-sources.md` его лицензия и условия использования.

### 6.2 Единая схема статьи

Поля: источник и его id, DOI, название, аннотация, год, язык, тип работы, лицензия, признак открытого доступа, ссылка на страницу оригинала, ссылка на бесплатный текст, журнал, область и тема, число цитирований, массив стран, авторы с организациями, исходная запись. Реализация в `db/schema.sql`.

### 6.3 Загрузка и обновление

- каждый источник подключается отдельным коннектором, который приводит данные к единой схеме;
- запись добавляется или обновляется по паре (источник, id источника);
- обновление по расписанию (не реже раза в неделю);
- лог каждого запуска: сколько записей получено, добавлено, обновлено, сколько ошибок.

### 6.4 Качество данных

- дедупликация записей из разных источников по DOI (позже по названию и авторам);
- записи без названия отбрасываются;
- аннотация и язык могут быть пустыми, интерфейс должен это корректно показывать.

## 7. Архитектура и технологии

```
Источники -> коннекторы (Python) -> PostgreSQL -> API -> сайт maqala.kz (Next.js)
```

| Слой | Технология |
|---|---|
| Загрузка данных | Python, requests, psycopg |
| База данных | PostgreSQL 16 (полнотекстовый поиск, GIN-индексы) |
| API | Next.js route handlers (решение фиксируется в `decisions.md`, при росте нагрузки выносится в отдельный сервис) |
| Фронтенд | Next.js, TypeScript, Tailwind CSS |
| Окружение | Docker Compose для локальной разработки |
| Хостинг | Vercel (сайт), Railway или Supabase (база) |
| CI | GitHub Actions: тесты и линтер на каждый push |

Поисковый движок (Meilisearch) подключается позже, если возможностей Postgres перестанет хватать.

## 8. API (черновик)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/works` | поиск и фильтры: `q`, `country`, `year_from`, `year_to`, `field`, `language`, `license`, `sort`, `page` |
| GET | `/api/works/{id}` | одна статья |
| GET | `/api/facets` | значения фильтров с количеством результатов |
| GET | `/api/countries` | список стран и количество статей |
| GET | `/api/countries/{code}` | статистика по стране |

Ответы в JSON, ошибки возвращаются с понятными кодами и сообщениями.

## 9. Требования к дизайну

- визуальное направление: выразительный современный стиль в духе галерей Awwwards, но читаемость важнее эффектов;
- единая дизайн-система: цвета, шрифты, отступы и компоненты вынесены в токены;
- светлая и тёмная темы;
- анимации сдержанные, отключаются при `prefers-reduced-motion`;
- шрифты должны корректно отображать кириллицу и казахские буквы (ә, ғ, қ, ң, ө, ұ, ү, һ, і);
- референсы и moodboard добавляются в `docs/design.md`;
- логотип и фирменный стиль выводятся из названия Maqala.

## 10. Юридические и этические требования

- хранятся только метаданные и ссылки, полные тексты не копируются;
- у каждой статьи отображается источник и лицензия;
- соблюдаются условия использования каждого источника данных;
- на странице «О проекте» указан контакт для запросов на удаление записи;
- перед запуском проверяется, не занято ли название Maqala похожим сервисом.

## 11. Тестирование

- модульные тесты нормализации данных каждого коннектора;
- тесты API (поиск, фильтры, граничные случаи: пустой запрос, нет результатов);
- ручная проверка на мобильных экранах и в обоих режимах темы;
- проверка поиска на русских, казахских и английских запросах.

## 12. Этапы и критерии приёмки

Подробный план задач по этапам: [ROADMAP.md](ROADMAP.md).

| Этап | Результат | Критерий готовности |
|---|---|---|
| 0. Подготовка | проверка и покупка доменов, репозиторий `maqala` на GitHub, свободные имена в соцсетях | домен зарегистрирован, репозиторий создан |
| 1. Фундамент | схема БД, коннектор OpenAlex | в базе не менее 1000 статей Казахстана, тесты проходят |
| 2. Поиск и API | эндпоинты поиска, фильтров, фасетов | запрос с фильтрами отвечает быстрее 1 с |
| 3. Интерфейс | главная, выдача, карточка статьи, страница страны, «О проекте» | все сценарии FR-1…FR-8 работают на десктопе и телефоне |
| 4. Дизайн и полировка | дизайн-система, темы, анимации, SEO | Lighthouse: Performance, Accessibility и SEO не ниже 90 |
| 5. Деплой | сайт доступен на maqala.kz | автоматический деплой из ветки `main` |
| 6. Развитие | казахстанские источники, другие страны, переводы интерфейса, монетизация | отдельный план после MVP |

## 13. Риски

| Риск | Что делаем |
|---|---|
| В международных базах казахстанские статьи покрыты неполно | подключаем локальные репозитории отдельными коннекторами |
| Лицензии и условия источников могут ограничивать использование | изучаем условия до подключения, храним только метаданные |
| Изменение API источника ломает загрузку | тесты коннекторов, логи, изоляция источников друг от друга |
| Плохой поиск на казахском и русском (морфология) | начинаем с простой конфигурации, потом улучшаем (Meilisearch или словари) |
| Домен .kz подчёркивает локальность, а идея шире | берём maqala.com для редиректа и защиты бренда, при росте можно сменить главный домен |
| Название занято или похоже на другой сервис | проверка в поиске и соцсетях до покупки доменов |
| Проект разрастается раньше времени | жёстко держим границы MVP из раздела 3 |

## 14. Принятые решения и открытые вопросы

**Принято:**
- название: Maqala;
- основной домен: maqala.kz, дополнительный maqala.com (если свободен);
- на старте единственный источник: OpenAlex;
- в MVP один язык интерфейса, но архитектура допускает i18n;
- API внутри Next.js.

**Открыто:**
- какие казахстанские источники подключаем первыми после MVP;
- когда и в каком виде включаем казахский и английский интерфейс;
- какая модель монетизации (решается после запуска MVP).
