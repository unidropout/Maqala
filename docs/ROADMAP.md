# План по этапам: Maqala

Документ раскладывает требования из [ТЗ](TZ.md) по этапам из раздела 12. Каждый этап состоит из задач-чекбоксов и заканчивается критерием готовности. Следующий этап начинается, когда критерий предыдущего выполнен (исключения указаны в разделе «Порядок и зависимости»).

Ссылки вида «ТЗ §6.3» и «FR-2» ведут к разделам и требованиям ТЗ.

## Этап 1. Фундамент: данные

**Цель:** в базе лежат нормализованные статьи из OpenAlex, загрузка повторяема и покрыта тестами.

**Источник** (ТЗ §6.1, §10)
- [x] Изучить лицензию и условия OpenAlex (лицензия данных, лимиты запросов, бесплатный ключ API) и записать в `docs/data-sources.md`.

**Схема БД** (ТЗ §6.2)
- [x] `db/schema.sql`: таблица статей со всеми полями единой схемы (источник и id в нём, DOI, название, аннотация, год, язык, тип, лицензия, признак OA, ссылки на оригинал и на бесплатный текст, журнал, область и тема, цитирования, массив стран, исходная запись в `jsonb`).
- [x] Авторы и организации: отдельные таблицы или `jsonb` (выбор записать в `decisions.md`).
- [x] Уникальный ключ `(source, source_id)` и индекс по DOI.
- [x] Таблица логов запусков: время, источник, получено, добавлено, обновлено, ошибки (ТЗ §6.3).
- [x] Способ применения схемы и миграций (скрипт или инструмент миграций).

**Коннектор OpenAlex** (ТЗ §6.3, §6.4)
- [x] Клиент OpenAlex на `requests`: постраничная выборка через cursor, повторы при ошибках, соблюдение лимитов.
- [x] Фильтр выборки: открытый доступ плюс страна авторов KZ (для старта).
- [x] Нормализация записи OpenAlex в единую схему (восстановление аннотации из `abstract_inverted_index`, страны из affiliations, лицензия, язык).
- [x] Отбрасывать записи без названия.
- [x] Upsert по `(source, source_id)` через `psycopg` с параметризованными запросами.
- [x] Дедупликация по DOI.
- [x] Запись лога каждого запуска.
- [x] Запуск из командной строки (`python -m ingest.openalex --country KZ`).

**Тесты и CI** (ТЗ §11)
- [x] Модульные тесты нормализации на сохранённых примерах ответов OpenAlex: полная запись, нет аннотации, нет языка, нет DOI, нет названия.
- [x] Линтер Python (например, ruff) и pytest в CI.

**Критерий готовности:** в базе не менее 1000 статей Казахстана, повторный запуск обновляет записи без дублей, тесты проходят в CI.

## Этап 2. Поиск и API

**Цель:** все эндпоинты из ТЗ §8 работают и отвечают быстрее 1 секунды.

**Полнотекстовый поиск** (FR-1, ТЗ §5, §13)
- [x] Колонка `tsvector`: название с весом A, аннотация с весом B.
- [x] Конфигурация, которая работает для русского, казахского и английского (на старте `simple` или комбинация словарей; выбор записать в `decisions.md`).
- [x] GIN-индекс по `tsvector`, индексы под фильтры (год, язык, лицензия, область, GIN по массиву стран).

**Каркас Next.js**
- [x] Проект Next.js + TypeScript в `web/`, подключение к Postgres из route handlers.
- [x] Линтер (ESLint), проверка типов и сборка в CI.
- [ ] Тесты API в CI.

**Эндпоинты** (ТЗ §8)
- [x] `GET /api/works`: `q`, `country` (мультивыбор), `year_from`, `year_to`, `field`, `language`, `license`, `sort`, `page` (FR-1, FR-2, FR-3, FR-4).
- [x] Сортировка по релевантности, дате и цитированиям (FR-3).
- [x] `GET /api/works/{id}` (FR-5).
- [x] `GET /api/facets`: значения фильтров с количеством результатов с учётом остальных фильтров (FR-2).
- [x] `GET /api/countries` и `GET /api/countries/{code}`: количество, распределение по годам и областям, последние и самые цитируемые (FR-6).
- [x] Валидация параметров, ошибки в JSON с понятными кодами и сообщениями.
- [ ] Ограничение частоты запросов к API (ТЗ §5).

**Тесты и производительность** (ТЗ §5, §11)
- [ ] Тесты API: поиск, сочетания фильтров, пустой запрос, нет результатов, неверные параметры, несуществующий id.
- [ ] Проверка поиска на русских, казахских и английских запросах.
- [ ] Нагрузочная проверка: догрузить базу или сгенерировать данные до ~1 млн записей, замерить время ответа, разобрать медленные запросы через `EXPLAIN ANALYZE`.

**Критерий готовности:** запрос с фильтрами отвечает быстрее 1 с при базе до 1 млн записей, тесты API проходят.

- [x] Общий макет: шапка с поиском, подвал со ссылкой на «О проекте».

**Страницы**

## Этап 4. Дизайн и полировка

**Цель:** у сайта есть фирменный стиль, обе темы, доступность и SEO на уровне запуска.

**Дизайн-система** (ТЗ §9)
- [ ] `docs/design.md`: референсы и moodboard.
- [ ] Логотип и фирменный стиль от названия Maqala.
- [ ] Токены: цвета, шрифты, отступы, радиусы, тени; компоненты собираются только из токенов.
- [ ] Шрифты с кириллицей и казахскими буквами (ә, ғ, қ, ң, ө, ұ, ү, һ, і), проверка на тестовой строке.
- [ ] Светлая и тёмная темы, переключатель, учёт системной настройки.
- [ ] Выразительные визуальные элементы главной в духе галерей Awwwards без потери читаемости.
- [ ] Сдержанные анимации, отключаются при `prefers-reduced-motion`.

**Доступность** (ТЗ §5)
- [ ] Контраст по WCAG AA в обеих темах.
- [ ] alt-тексты, видимый фокус, семантическая разметка.

**SEO** (ТЗ §5)
- [ ] meta-теги и Open Graph для каждой статьи и страны.
- [ ] `sitemap.xml` (с разбиением на части при большом числе статей) и `robots.txt`.
- [ ] Структурированные данные (schema.org `ScholarlyArticle`).

**Проверка** (ТЗ §11)
- [ ] Ручная проверка на мобильных экранах в обеих темах.
- [ ] Lighthouse по главной, выдаче, статье и стране.

**Критерий готовности:** Lighthouse: Performance, Accessibility и SEO не ниже 90.

## Этап 5. Деплой

**Цель:** сайт открыт на `maqala.vercel.app`, данные обновляются сами, деплой автоматический.

**Инфраструктура** (ТЗ §7)
Всё на бесплатных тарифах, без затрат.

- [ ] База в продакшене: Supabase (бесплатный тариф, до 500 МБ), применить схему.
- [ ] Уложиться в лимит 500 МБ: загружать статьи Казахстана, не хранить лишнее из исходной записи, следить за размером базы.
- [ ] Сайт на Vercel (бесплатный тариф), секреты только в переменных окружения.
- [ ] Автоматический деплой из ветки `main`.
- [ ] Адрес `maqala.vercel.app` (проверить, что имя свободно в Vercel).

**Данные** (ТЗ §6.3)
- [ ] Первичная загрузка в продакшен-базу.
- [ ] Обновление по расписанию не реже раза в неделю (например, GitHub Actions по cron).
- [ ] Оповещение, если запуск загрузки упал или выдал много ошибок.

**Надёжность** (ТЗ §5, §13)
- [ ] Сбой загрузки или источника не ломает сайт: сайт работает на уже загруженных данных.
- [ ] Резервное копирование базы (регулярный `pg_dump`, например через GitHub Actions).

**Перед запуском** (ТЗ §10)
- [ ] У каждой статьи видны источник и лицензия.
- [ ] Контакт для удаления записи работает.
- [ ] Повторная проверка, что название не занято похожим сервисом.

**Критерий готовности:** сайт доступен на `maqala.vercel.app`, автоматический деплой из ветки `main` работает.

## Этап 6. Развитие (после MVP)

Отдельный план составляется после запуска MVP. Кандидаты:

- [ ] Собственный домен, когда появятся средства: проверить и купить maqala.kz (и maqala.com, если свободен), решить вопрос хостинга в Казахстане (требование зоны .kz), настроить DNS и редирект maqala.com → maqala.kz (ТЗ §1, §13).
- [ ] Казахстанские источники: репозитории вузов и журналы, по одному коннектору, каждый с записью в `docs/data-sources.md` (ТЗ §6.1, §13).
- [ ] CORE и Crossref (ТЗ §6.1).
- [ ] Дедупликация по названию и авторам (ТЗ §6.4).
- [ ] Страницы других стран.
- [ ] Казахский и английский интерфейс (ТЗ §14).
- [ ] Улучшение морфологии поиска: словари или Meilisearch (ТЗ §7, §13).
- [ ] Модель монетизации (ТЗ §14).

## Порядок и зависимости

```
0 Подготовка -> 1 Данные -> 2 Поиск и API -> 3 Интерфейс -> 4 Дизайн -> 5 Деплой -> 6 Развитие
```

Что можно делать параллельно:
- этапы 1–4 идут локально и бесплатно, внешние сервисы нужны только к этапу 5;
- moodboard и логотип (этап 4) можно начинать во время этапов 1–2;
- страницы этапа 3 можно верстать на моковых данных, пока заканчивается API этапа 2;
- пробный деплой на поддомен Vercel можно сделать сразу после этапа 3, чтобы не копить проблемы к этапу 5.
